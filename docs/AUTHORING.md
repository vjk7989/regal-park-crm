# Authoring module definitions (Phase B rules)

Read: `docs/PLAN.md` §10.1 (types), `docs/MODULES.md` (your modules: pages, columns, statuses, flavour), and `shared/modules/ops2.ts` (Fleet — the reference style). Your file exports `export const MODULES: ModuleDef[] = [...]`.

1. **One ModuleDef per catalogue module**, `key` exactly as in MODULES.md (backticked), `group` = the MODULES.md section ("Sales & CRM" / "Operations" / "People" / "Marketing" / "Tools"; Accounting & Cost Management use "Finance"), `icon` = a real lucide-react icon name (e.g. Truck, Wrench, Users, Factory, Package, ShoppingCart, Calculator, ClipboardCheck, Calendar, FileSignature, Megaphone, BarChart3, ShieldAlert, KeyRound, FolderOpen, Sheet, Briefcase, GraduationCap, Target, HardHat, Store, Gift, Handshake, Award, Boxes, Building2, Workflow, Headset, Share2, Star, AtSign, Wallet, Receipt, Landmark).
2. **Pages in the catalogue order**: D → `{kind:'dashboard'}`, T → `{kind:'table', entity}`, R → `{kind:'report'}` (optionally `entities`), S → `{kind:'settings'}`, C → `{kind:'calendar'}`, placeholder pages (Media, Bulk PDF Export, analytics with no data) → `{kind:'info', text}`. Every T page has its own entity.
3. **Entities**: `key` = `<moduleKey>_<plural_snake>` (globally unique). Give `prefix` (2–4 letters + '-') to transactional entities (orders, tickets, invoices, work orders…), `titleField`, `statusField` (select field named `status` using the catalogue's status list), `dateField`, `amountField` where they exist. 4–9 fields each, covering the catalogue columns that matter (skip noise columns like "Options", "Action", custom test columns). `seedCount` 8–15 (lookups 4–8). Use `kanban: true` for pipeline-like entities (tasks, tickets, candidates, campaigns) and `calendar: true` for appointment/booking/schedule/interview entities with a date.
4. **Settings**: 2–4 `settings` fields (prefixes, defaults, toggles) and 1–3 `lookup: true` entities for the module's settings tabs (categories, types, groups) — each with a `name` field and a `pool`.
5. **Refs**: only to core collections (`clients`, `users`, `properties`, `staff`, `agents`, `brokers`, `owners`, `leads`) or to entities in the SAME module. Never to another module or another file.
6. **Mock data = Sterlitee Developers (Bengaluru real-estate developer)**. Fill `pool` with ≥ 6 realistic Indian, on-brand values for every text field that would otherwise be generic (names of products, materials, services, campaigns, subjects, descriptions). Use `gen` for people/companies/phones/emails/addresses/dates/plates/serials. Money in INR with sensible `min`/`max`. Numeric pools are strings (they get coerced). Never seed anything that looks like a real password or secret.
7. **Verify** (light, safe in parallel): `npx tsx scripts/seed.ts --check` (exit 0, no integrity errors, no "note: empty ref" for your entities) — it never writes files. Do NOT run the normal seed, vitest, or vite build. Run `npx tsc --noEmit -p .` once at the end. Don't commit. Don't touch files other than yours.
